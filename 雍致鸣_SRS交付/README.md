# StudyFlow：雍致鸣部分交付说明

## 内容与使用

首先阅读`StudyFlow_SRS_雍致鸣部分.md`。这是可直接合入总SRS的章节正文，含：

- 角色权限矩阵与12个用例简述。
- UC-04、UC-08两项详细用例及异常、验收场景。
- 12条统一业务规则和18个领域术语。
- 非功能需求、AI质量要求和量化指标接口。
- A-F01～A-F08需求追踪及规则验证覆盖。
- 一项已核对出版社信息的书籍及47词英文注释。

`assets/`包含4张PNG和对应SVG：用例图两个视图、主业务流程两个阶段。将正文与该文件夹一起移动，Markdown中的相对图片链接仍然有效。

`models/StudyFlow_用例与主业务流程.drawio`是可编辑源文件，含图A～D四个页面，可在draw.io/diagrams.net中打开。SVG适合放大和插入排版，PNG便于直接查看。所有图均由本地代码绘制。

`support/个人贡献与AI使用记录.md`提供本次透明的贡献说明及AI使用记录；`support/build_models.py`可重新生成模型和展示图，需要Python及Pillow。脚本默认使用Windows微软雅黑字体。

## 分析决定与建议阈值

以下细化是为了让规格闭合，本稿已经给出完整行为，不是已获教师认可的新要求：

1. P0任务依赖限制在同一作业内，跨作业仅共享时间占用检查。
2. 普通成员可查询和提出建议，正式排程/调整草案由管理者发起。
3. 草案仅因规划相关输入变化失效，不因评论、标题等无关元数据变化无故失效。
4. 计划整体确认与通知投递分离，后者失败保留可重试事件。
5. 单次0.50元、6次模型请求、8次工具调用、通知60秒及并发回归轮数为新增拟定阈值；总预算300元及主要质量目标沿用第一次成果。

本部分不包括其他成员负责的完整引言、SWOT/TOWS、路线图、4个UI原型及其4项详细用例。因此这个文件夹是个人部分的交接包，应在小组完整报告中合并后提交。已有测试场景是验收设计，尚无运行系统或用户实验结果。
